# Project Architecture Rules

- Party home uses a separate paused, poster-backed Enter Story video; preserve other background loops.
- Dice profiles use resolveOddsForContext per roll, because combat and roleplay odds can differ.
- Overlays above open drawers render inline inside drawer content, without body portals, and carry data-vaul-no-drag; modal drawers trap focus and close on outside taps, so z-index alone cannot work.
- npc-combat carries identical copies of npc-reply's handler/models/repo/prompt in npc-combat/npc-reply/, because each server function deploys only its own folder; a test fails if the copies drift, so re-copy after editing npc-reply.
- Party launch forwards an explicit initial Live Table choice through the screen chain; locally owned drawer state prevents Return to Story reopening it.
- Cache Live Table separately from DM narration by account and party; successful reads replace stale rows but preserve in-flight changes; failed reads retain visible conversation.
- Arena Live Table Sparring renders the real PartyDMScreen through runtimeOverrides with local Arena hooks; never rebuild a separate mock table, because a second copy drifts from the live game.
- Party Sparring runs on the host's phone and is shared over a live broadcast channel (no database rows); members mirror the host's fight and send actions to it, because campaign tables and the fight referee must never see practice fights.
- Campaign Map world geography lives in party_shared_state (state_type 'campaign_map') with all math in src/lib/campaign-map.ts; never reuse the combat map_markers state, because tactical positioning and world travel have different rules.
- Custom companions are drawn in code on a canvas (src/components/companion/CompanionCanvas.tsx) from the saved look in src/lib/companion-rig.ts; never ship per-look image files, because every look must stay customizable and tiny to save.
- Atlas: one versioned envelope (src/lib/campaign-atlas.ts) in campaign_map. App writes use write_campaign_atlas compare-and-set, patching one captured map id to prevent stale replay loss. Connector installs alone use service-only bridge_install_campaign_area with locking/version checks, never host impersonation; contract/recovery: docs/bridge-campaign-install.md, latest SQL: drizzle/migrations/0030_fix_bridge_install_guide_alias_apply.sql.
- Flight stores temporaryFlight outside roads; travelRoute/savedTravelRoute resolve it. Server eligibility matches saved flight geometry, segment and timing, never fabricates paths; ground routing stays isolated and midair cancellation preserves position.
- City-scale travel is a per-map travelScale flag inside campaign map state (not a new atlas navigation mode), so the server atlas validator and all travel/clock math stay shared; city only lifts the travel-day cap and changes wording.
- Travel Director: hash destination/pace/legs, check map_id/miles; lock plan/sync/arm. Reuse outcomes, original-host QStash pre-arm, atomic start; cancel rejected receipts. Overland Begin/Continue/Resume await public-only launch + refresh from paused state to prevent unprepared movement; city anchors unchanged. Unprojectable targets fail closed; orphan callbacks inactive. Firing uses leases and atomic complete_travel_event_post.
- Party signup onboarding runs through party-link onboarding_* actions calling service-role-only onboarding_* database functions (drizzle/migrations/0031_party_onboarding_foundation.sql); a seat and save are created together only at finalize, and a BEFORE INSERT guard on party_members enforces the seat limit and one active party for every join path, because separate client checks race.
- Party creation context is built only server-side in supabase/functions/_shared/party-creation-context.ts (host party guides + dm_session summary + read-only atlas-path area guides, secret markers stripped, one bounded extraction call, lease-coalesced cache keyed by source fingerprint); the creator's partyCreationSessionId branch receives only that projection, because raw GM material must never reach the browser or the chat model.
- Party signup hand-off builds the new save only in the pure src/lib/ai-creation/party-build-save.ts (session-derived IDs, explicit scoped keys, never the active hero's state) and opens play through a one-shot account-level receipt that Index re-verifies with onboarding_resume before loading that exact save, because generic restore/pending-AI paths would otherwise load or overwrite the wrong character.

- Live Table speech artwork uses nine-slice borders and a separate tail above naturally sized portraits, because stretching a whole frame distorts corners and crops speakers.
- Buff metadata is validated in spellResolve and deploy-local npc-combat rules; edits preserve fields. Temp HP enqueues separate deltas atomically through the existing acknowledged inbox, never ordinary HP.

- Scene videos store private paths; replace by upload, conditional row update, then old-file cleanup. Sign per path with one retry, because URLs expire and stale replacements must not erase attachments.
- Chat-avatar reads are owner-or-shared-party scoped (including hosts), and gear-image updates/deletes require Storage owner_id, because unrelated accounts must not read player identities or alter their files.
- Solo Empyrean actions enter through empyrean-rules with owner authentication; timer callbacks validate hashed event tokens. Rule state, rider mastery, map time and result inbox commit through service-only empyrean_commit; owner atlas saves use write_solo_campaign_atlas, because solo rules must remain atomic and isolated from party data.
- Campaign map hooks access map rows, guides and travel through CampaignMapStore, defaulting to PARTY_MAP_STORE; image uploads stay separate so solo storage can reuse map logic without changing party behavior.
- Solo fight rules are pure functions in empyrean-rules/combat.ts with caller-supplied time and randomness; its minigames.ts stays byte-identical to the party and phone copies because function deployments cannot import sibling function folders.
- Prodigy rules stay byte-identical in the solo function and phone modules, with a parity test, because deployments cannot import app files; absent class or fight tier retains ordinary rider rules.
- Solo-only engine classes use the empyreanOnly registry flag to stay out of ordinary pickers; Prodigy HP uses its registered die while other characters retain the legacy formula, preventing changes to existing heroes.
- Solo Prodigy phone controls derive tier from character context and pass riderClass through rules and fight sheets; Battle Brief uses are server-counted before appending the binding line to the existing composer, avoiding a second action path.
- Creation assistants import character rules and the JSON template from _shared/creation-rules.ts to prevent their accepted fields and IDs from drifting.
- Empyrean onboarding keeps its text in a pure prompt module and validates the signed-in user before AI calls; lore and rider context are bounded to keep requests isolated and predictable.
- Rider onboarding stores its draft and staged launch outside character scope, applying campaign setup only after the new save exists, so character creation cannot lose its hand-off on the first save.
- The rider onboarding page uses the existing aiCreatedCharacter hand-off and carries its draft through optional Empyrean account switching, so creation stays on the existing save path.
- Empyrean onboarding launches pass explicitly through Index, Home and the hub; fresh campaigns retain the launch's starting place and event choice until the solo engine opens, so existing manual entry defaults stay unchanged.
- Solo Empyrean opening sends use a ref-backed hook with latest callbacks and a once-only clear step, because re-renders must not restart the timer or erase later chat.
- Solo Live NPCs use campaign-owned solo_npcs rows and an isolated solo-npc helper with era-gated canon minds; existing voicing takes an optional mind block, so party NPC systems remain unchanged.
- Solo Empyrean Live Table reuses RoundChatDrawer with the Arena local chat hook and voiceNPC off-feed mode; never build a second table UI, so solo and party stay identical.
- Solo table NPC actions use the solo roster and local conversation only; roll requests share the solo referee with manual whispers, because party membership and combat rows must not be touched.
- Solo starter-guide recovery matches saved map IDs and inserts only missing identities; guide reads reject stale campaign responses, because retries must preserve edited guides and campaign isolation.
- Solo Empyrean built-in art lookups (dragon by color, foe by cast name then kind, arena backdrops, scene art) live in src/lib/empyreanArt.ts; BattleStage takes an optional backdrop so party fights keep the flat field.
- Solo NPC urge scoring stays pure and separate from era-gated temperament profiles, because speech timing must be testable without AI requests or screen state.
