

# Strip AI DM HUD Footers from TTS Narration

## Problem

AI DM messages contain structured "HUD" footer sections — Quest HUD, Party Status, Combat Log, etc. — delimited by lines of `═` characters and bracketed headers like `[QUEST HUD]`. These are game-state metadata, not narrative prose, but the narrator reads them aloud, breaking immersion.

## Root Cause

The HUD footers are generated by the AI model (likely instructed by custom GM guides or persona prompts). They are not hardcoded in the system prompt, so we cannot suppress them at the source without risking breaking the visual game-state display users rely on. The correct fix is to strip them at the TTS processing layer.

## Changes

### File: `src/lib/tts-utils.ts` — `stripMarkdownForTTS()`

Add four new regex rules **before** the final `trim()`, in this order:

1. **Truncate at first `═══` separator line** — The narrative always comes before the HUD. Everything from the first line containing 3+ `═` characters onward is metadata and should be removed entirely. This is the primary, most reliable rule.

   ```typescript
   result = result.replace(/^[═]{3,}.*[\s\S]*$/m, '');
   ```

2. **Fallback: Strip bracketed HUD section headers** — In case a message uses headers without `═` separators (e.g. `[QUEST HUD]`, `[PARTY STATUS]`, `[COMBAT LOG]`, `[LOOT]`, `[MAP]`, `[STATUS]`, `[INVENTORY]`), remove the header line and all following lines until the next blank line or end of text.

   ```typescript
   result = result.replace(/^\[(?:QUEST HUD|PARTY STATUS|COMBAT LOG|LOOT|INVENTORY|MAP|STATUS|WORLD STATE)\][\s\S]*$/gim, '');
   ```

3. **Remove decorative Unicode divider lines** — Catch leftover `───`, `═══`, `▬▬▬`, `╔══`, `╚══` etc. that aren't meaningful speech.

   ```typescript
   result = result.replace(/^[═─▬╔╗╚╝╠╣║│┌┐└┘├┤┬┴┼]{3,}.*$/gm, '');
   ```

4. **Strip emoji-prefix status lines** — Catch lines like `► Current Objective:`, `• Atlas (HP: 45/45)`, `⚔ Combat Round 3` that may survive the above rules.

   ```typescript
   result = result.replace(/^[►▶•●⚔🗡️🛡️⚡💀🎯📍🗺️☠️✦✧◆◇■□▪▫]\s*.+$/gm, '');
   ```

### Order within `stripMarkdownForTTS()`

These four rules should be added **at the top** of the function, before any markdown stripping. Rationale: the `═══` truncation rule is the most aggressive and should run first to discard the entire footer block before the markdown rules process it into harder-to-match plain text.

## Files Changed

| File | Change |
|------|--------|
| `src/lib/tts-utils.ts` | Add 4 regex rules to `stripMarkdownForTTS()` |

## What is NOT changed

- The AI DM system prompt and edge function are untouched — the HUD is still generated and displayed visually.
- The narrator hook (`use-narrator.ts`) is untouched — it already calls `stripMarkdownForTTS` before sending to ElevenLabs.
- No other files are affected.

## Testing

1. Trigger narration on an AI DM message that contains `═══` separators with `[QUEST HUD]` and `[PARTY STATUS]` — verify only the story portion is narrated
2. Trigger narration on a short message with no footer — verify it narrates normally with no truncation
3. Trigger narration on a message with `---` markdown horizontal rules — verify no regression (these are already handled by existing rules)
4. Verify the HUD sections still display correctly in the chat UI (they should, since we only strip for TTS, not for rendering)
